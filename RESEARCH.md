# Исследование: похожие open-source проекты

Дата: 29.10.2026. Поиск по GitHub вели три субагента по трём темам: ипотечные калькуляторы с досрочным погашением, учёт бюджета, закрытие долгов и финансовые цели. Звёзды, дату последнего коммита и лицензию у финалистов я перепроверил через GitHub API. Наличие упомянутых файлов исходников тоже проверено.

## Главный вывод

**Готового зрелого проекта, который делает то же, что «Финиш», нет.** Ипотечные калькуляторы обычно маленькие хобби-проекты, и режимы «уменьшить срок» и «уменьшить платёж» рядом почти нигде не показаны. Большие бюджетные приложения (Actual, Firefly III) не умеют планировать закрытие нескольких долгов. Подсказок вида «на кафе на 25% больше обычного» нет ни у кого.

Поэтому расчётное ядро пишем сами (это 150–300 строк на TypeScript), а из чужих проектов берём проверенные формулы, идеи интерфейса и модели данных. Код копируем только из проектов под MIT или CC0 и сохраняем уведомление об авторских правах.

## 5 лучших примеров

### 1. Zaynulla/mortgage — эталон «срок или платёж» для России

- **Ссылка:** https://github.com/Zaynulla/mortgage. Сопроводительная статья на Хабре: «Сокращать срок или платёж — раскрываем черный ящик ипотечного калькулятора», https://habr.com/ru/companies/infowatch/articles/868162/
- **Стек:** Python, Jupyter. Логика в `libs/mortgage.py`.
- **Насколько живой:** ★3, последний коммит 22.12.2024. Это законченный справочный проект, а не развивающийся продукт.
- **Лицензия:** MIT.
- **Расчёты:** аннуитетный платёж. Досрочные погашения размечены отдельно на «сокращающие срок» и «сокращающие платёж». Новый срок считается по формуле `n = −ln(1 − i·S/P) / ln(1+i)`. Есть платёж больше обязательного (то есть постоянная ежемесячная досрочка) и помесячный график.
- **Что взять:** самую точную для российских банков модель двух режимов. Статья подходит как спецификация, а формулы — чтобы сверить наши тесты. По MIT код можно переносить на TS.

### 2. paulhoughton/mortgage — переплата каждый месяц и график «было / стало»

- **Ссылка:** https://github.com/paulhoughton/mortgage. Демо: https://paulhoughton.github.io/mortgage
- **Стек:** React (хуки) и D3.
- **Насколько живой:** ★318, самый популярный в своей теме. Последний коммит 13.09.2022, проект спит, но стабилен.
- **Лицензия:** MIT.
- **Расчёты:** аннуитет, постоянная ежемесячная переплата и список разовых переплат по месяцам. Сравнивается остаток долга с переплатами и без, считаются проценты по годам. Тесты в `src/__tests__`.
- **Чего нет:** режима «уменьшить платёж», только сокращение срока.
- **Что взять:** цикл в `src/calculations.js` (около 50 строк) почти совпадает с нашим сценарием «+5/10/20 тыс. в месяц». Главное — график двух линий остатка долга (без досрочки и с ней) с закрашенной разницей. Именно этот визуальный приём заложен в IDEA.md.

### 3. aashir-athar/solvent — «дата свободы от долгов» на телефоне

- **Ссылка:** https://github.com/aashir-athar/solvent
- **Стек:** Expo / React Native, TypeScript, данные только на устройстве (SQLite).
- **Насколько живой:** ★1, весь проект появился разом 08.06.2026, с тех пор изменений нет. Молодой и непроверенный, но по замыслу ближе всех к нам.
- **Лицензия:** MIT, и у репозитория, и у ядра `src/core/solvent-core`.
- **Расчёты:** очерёдность гашения долгов «лавиной» (сначала дорогой), «снежным комом» (сначала маленький) или вручную. Освободившийся платёж переходит на следующий долг. Помесячный план и точная дата закрытия, дата достижения цели накоплений (`savings.ts`), рубежи прогресса. Деньги хранятся в целых копейках. Есть тесты на эталонных примерах и 1000 случайных проверок.
- **Что взять:**
  - *Идеи:* одна большая дата на главном экране. Ползунок «что если», который показывает только посчитанные ядром цифры. Подсказки, которые пересказывают расчёт и ничего не выдумывают. Рубежи только за реальный прогресс. Табличные цифры и один акцентный цвет.
  - *Код:* ядро `payoff.ts` написано на чистом TS без зависимостей и подходит как основа логики распределения досрочки между ипотекой и потребительским кредитом.

### 4. Actual Budget — эталон локального бюджета

- **Ссылка:** https://github.com/actualbudget/actual
- **Стек:** TypeScript, React, SQLite прямо в браузере, необязательный сервер синхронизации.
- **Насколько живой:** ★29,8 тыс., коммиты ежедневно (последний 28.10.2026), релиз каждый месяц. Очень живой.
- **Лицензия:** MIT.
- **Расчёты:** бюджет «по конвертам» с переносом остатка между месяцами, регулярные доходы и платежи, правила автокатегоризации, отчёты по тратам и денежному потоку. Шаблоны целей умеют «заложить в бюджет среднее за последние N месяцев» (`packages/loot-core/src/server/budget/goal-template.ts`) — это ближе всего к нашей «обычной сумме расходов». Импорт CSV/OFX/QIF, экспорт в один файл.
- **Что взять:** деньги в целых копейках, разделение данных на категории, операции и регулярные платежи. Логику «норма по истории», заменив среднее на медиану за 3 месяца. Резервную копию одним файлом.
- **Что не брать:** модель «конвертов» для нас тяжеловата, а SQLite в браузере избыточна по сравнению с IndexedDB.

### 5. ezBookkeeping — быстрый ввод трат на телефоне

- **Ссылка:** https://github.com/mayswind/ezbookkeeping
- **Стек:** сервер на Go, интерфейс на Vue 3, мобильная версия в виде PWA.
- **Насколько живой:** ★5,9 тыс., коммиты ежедневно (последний 28.10.2026), релизы несколько раз в месяц. Очень живой.
- **Лицензия:** MIT.
- **Расчёты:** двухуровневые категории, шаблоны операций, регулярные операции, статистика и графики трендов, много форматов импорта. Работает только с сервером, без него офлайн не обойтись.
- **Что взять:** порядок ввода на телефоне: сначала цифровая клавиатура для суммы, потом сетка категорий, дата по умолчанию сегодня. Шаблоны операций «в одно касание» (например, «Зарплата» или «Бензин»). Форматирование сумм с учётом локали.

Код из проектов под GPL и AGPL нельзя переносить в наш проект: тогда весь проект пришлось бы открыть под той же лицензией. Из проектов без лицензии копировать код нельзя вообще.

## Что меняем в плане

1. **Своё ядро расчётов.** Формулы сверяем с Zaynulla/mortgage и paulhoughton/mortgage и записываем их примеры как эталонные тесты.
2. **Деньги в целых копейках**, как в Actual и Solvent, чтобы не копились ошибки округления. Платёж округляем до копейки, как в банке.
3. **Проценты по фактическому числу дней в месяце**, как в российских банках. Ни один из найденных проектов так не делает. Это улучшит совпадение с графиком банка, но можно отложить на версию 2.
4. **Распределение досрочки между кредитами** на базе логики Solvent: «лавина», «снежный ком» или вручную.
5. **График «трёх будущих»** на экране сценариев: без досрочки, текущий план, план с выбранной прибавкой.
6. **Обратная цель:** «Сколько добавлять в месяц, чтобы закрыть ипотеку к году X».
7. **Быстрый ввод трат:** сначала сумма, потом сетка категорий. Название запоминает категорию.
8. **Надёжность данных:** просим браузер не удалять данные (`navigator.storage.persist()`), экспортируем резервную копию в один JSON-файл через «Поделиться» в Файлы или iCloud, напоминаем «копия сделана N дней назад».
